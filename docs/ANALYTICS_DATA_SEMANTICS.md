# Analytics Data Semantics & Metric Normalization

**Status:** Authoritative Specification  
**Source of Truth:** Verified against official Umami v2/v3 SQL queries (`getPageviewMetrics.ts`, `getWebsiteStats.ts`, `getEventMetrics.ts`)

---

## 1. Metric Definitions & Aggregation Semantics

Mislabeling analytics metrics destroys stakeholder trust. This document specifies the precise mathematical definition of every metric retrieved from Umami and defines its mandatory Persian presentation label.

| Metric Identifier | Umami Underlying SQL / Aggregation | Exact Technical Definition | Canonical Persian Label | Forbidden Translations / Labels |
| :--- | :--- | :--- | :--- | :--- |
| **Visitors** | `uniq(session_id)` or `count(distinct session_id)` | Unique browser sessions generated by distinct visitor IDs within the period. | **کاربران یکتا** | ❌ بازدیدها, ❌ کلیک‌ها, ❌ نمایش‌ها |
| **Visits** | `uniq(visit_id)` or `count(distinct visit_id)` | Number of discrete browsing visits/sessions (separated by 30-min inactivity). | **نشست‌ها** | ❌ کاربران, ❌ بازدیدکنندگان |
| **Pageviews** | `sum(views)` or `count(*)` where event_type != 2 | Total page render requests. | **نمایش صفحات** | ❌ کاربران, ❌ نشست‌ها |
| **Bounce Rate** | `(bounces / visits) * 100` | Percentage of visits that loaded only a single page without secondary interaction. | **نرخ پرش** | ❌ خروج, ❌ افت ترافیک |
| **Visit Duration** | `sum(max_time - min_time) / visits` | Average time spent browsing per visit. | **میانگین زمان نشست** | ❌ مدت حضور کاربر |
| **Top Pages (`url_path`)** | `count(distinct session_id)` as `y` in `/metrics?type=path` | Number of **unique visitors** who viewed this path. | **صفحات پربازدید (کاربر)** | ❌ تعداد دفعات نمایش صفحه (اگر از `/metrics` خوانده شود) |
| **Top Referrers** | `count(distinct session_id)` as `y` in `/metrics?type=referrer` | Number of **unique visitors** arriving from this external domain. | **منابع ارجاع (کاربر)** | ❌ کلیک‌های ورودی |
| **UTM Source / Medium** | `count(distinct session_id)` as `y` in `/metrics?type=utmSource` | Number of **unique visitors** originating from this campaign parameter. | **کمپین‌ها / کانال‌ها (کاربر)** | ❌ تعداد کلیک کمپین |
| **Custom Events** | `count(*)` as `y` in `/metrics?type=event` | Total occurrences of the designated event action. | **رویدادهای کلیدی (تعداد اجرا)** | ❌ کاربران انجام‌دهنده (چون `count(*)` است نه `count(distinct session_id)`) |

## 2. Umami API Endpoint Semantics

### 2.1 Summary Stats: `GET /api/websites/{websiteId}/stats`
- **Request Parameters**:
  - `startAt`: Epoch milliseconds (inclusive).
  - `endAt`: Epoch milliseconds (inclusive).
  - `compare`: `'prev'` (comparison against preceding window of identical duration).
- **Verified Response Payload**:
  ```json
  {
    "pageviews": 4200,
    "visitors": 1850,
    "visits": 2100,
    "bounces": 630,
    "totaltime": 315000,
    "comparison": {
      "pageviews": 3800,
      "visitors": 1700,
      "visits": 1950,
      "bounces": 680,
      "totaltime": 273000
    }
  }
  ```
  *(Note: Normalizer also handles legacy Umami v1/early-v2 shapes like `{ pageviews: { value: 4200, prev: 3800 } }`).*

### 2.2 Metrics Breakdown: `GET /api/websites/{websiteId}/metrics`
- **Request Parameters**:
  - `type`: `'path'` (or `'url'`), `'referrer'`, `'utmSource'`, `'utmMedium'`, `'utmCampaign'`, `'utmContent'`, `'event'`.
  - `startAt`, `endAt`: Epoch milliseconds.
  - `limit`: Number of rows to return (default: 5).
  - Optional filters: e.g. `utmSource=Instagram` when querying `type=utmContent`.
- **Return Type**: `Array<{ x: string, y: number }>`
- **CRITICAL SEMANTIC FINDING**:
  - In Umami's SQL queries (`src/queries/sql/pageviews/getPageviewMetrics.ts`), the query groups by dimension `x` and calculates:
    `count(distinct website_event.session_id) as y`
  - **Therefore, `y` in `/metrics` is ALWAYS unique visitors, NOT pageview count!**
  - Exception: For `type=event`, `y` is `count(*)`, representing total event triggers.

## 3. Comparison & Percentage Calculation Rules

$$\Delta\% = \frac{\text{Current} - \text{Previous}}{\text{Previous}} \times 100$$

### Special & Edge Case Rules:
1. **Both values zero (`current = 0, prev = 0`)**:
   - Change: `0%`
   - Formatted: `⚪️ 0%`
2. **Growth from zero (`current > 0, prev = 0`)**:
   - Previous period had no recorded instances.
   - Formatted: `🟢 +N (جدید)` (e.g., `+18 (جدید)`) instead of `+Infinity%` or `+100%`.
3. **Drop to zero (`current = 0, prev > 0`)**:
   - Formatted: `🔴 -100%`.
4. **Metric Polarity (Inverted Metrics)**:
   - For **Bounce Rate**, an increase is bad (🔴) and a decrease is good (🟢).
   - For all other metrics (Visitors, Visits, Pageviews, Events), an increase is good (🟢) and a decrease is bad (🔴).

## 4. BiDi Typography & Persian Formatting Standards

To prevent Telegram's Bidirectional text engine from flipping signs, numbers, or URLs:

1. **Directional Markers**:
   - Prepend `\u200F` (Right-to-Left Mark / RLM) at the start of lines with emojis or mixed text.
   - Wrap percentage changes in Left-to-Right marks (`&lrm;` / `\u200E`), e.g., `\u200E+14.5%`.
2. **Numeric Representation**:
   - Metric quantities are formatted with standard Latin digits and thousand separators: `1,842`. (Persian digits in Telegram client text frequently flip adjacent `/` or `%` characters).
3. **Paths & Technical Keys**:
   - Enclose URLs, paths, and UTM values inside `<code>...</code>` tags to guarantee monospaced, LTR rendering:
     `<code>/products/item-1</code>`.
